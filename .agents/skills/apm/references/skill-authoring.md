# 스킬 작성·정제

## 사용자 선호를 규칙으로 쓰기

사용자의 명시적 수정·금지·예외 요청과 기존 스킬·저장소 규칙에서 선택할 기본값을 찾습니다. 알려진 관례라는 이유로 사용자 선호를 삭제하지 않습니다.

- 최신 명시적 요청이 기존 규칙을 바꾸면 소유자의 정본을 갱신합니다. 요청이 충돌하고 적용 범위로도 나뉘지 않을 때만 충돌한 선택지를 질문합니다.
- 기본값은 바로 씁니다. 다른 선택이 필요한 경우에만 관찰 가능한 조건과 그때의 행동을 붙입니다. “상황에 따라 조정”처럼 선택을 정하지 못하는 규칙은 구체화할 근거가 없으면 삭제합니다.
- 사용자 요청·기존 규칙·실제 계약으로 설명할 수 없는 제한은 넣지 않습니다. 외부 작성 지침을 근거로 임의의 단어 수·문장 형식·필수 절차를 추가하지 않습니다.
- 표현만 정제할 때는 계약·금지·승인·예외·검증 의무와 기존 제목·목록·강조·작성자용 HTML 힌트를 보존합니다. 정보 위치 변경도 요청받았다면 내용·힌트를 빠뜨리지 않고 옮깁니다.

규칙마다 적용 결과를 볼 산출물·비교 대상·성공 조건을 정합니다. 기본값과 명시한 예외의 사례를 대조하되, 사례 검토와 실제 실행 검증은 구분해 보고합니다.

## 정보 배치

| 위치            | 담을 정보                                                           |
| --------------- | ------------------------------------------------------------------- |
| `name`          | 스킬 식별자                                                         |
| `description`   | 선택에 필요한 대상·수행할 작업·사용 상황                            |
| `SKILL.md` 본문 | 공통 실행 조건·기본 절차·판단 기준·완료 조건                        |
| `references/`   | 특정 조건에서 필요한 상세 예제·절차; 본문에서 읽을 조건과 경로 연결 |

스킬 선택에는 [먼저 제공되는 이름·설명](https://agentskills.io/specification#progressive-disclosure)을 사용합니다.
본문의 `사용 시점` 절은 `description`에 없는 적용 조건이 필요할 때 둡니다.

## 조건과 행동 쓰기

“필요하면 다른 문서를 참고” 대신 “원격 MCP 연결 요청이면 HTTP 예제와 인증 조건을 확인”처럼 읽을 조건과 할 일을 연결합니다. 예외가 없는 기본 행동에는 조건절을 덧붙이지 않습니다.
절·표·템플릿은 선택이나 실행 순서를 찾는 데 필요할 때만 사용합니다. 모든 규칙을 표로 만들거나 모든 스킬에 같은 절을 채우지 않습니다.
행동을 정하지 않는 목적 소개·일반론, 다른 소유자의 규칙, 앞에서 정한 행동을 되풀이하는 요약은 삭제합니다. 예제에는 판단이 필요한 입력과 기대 결과를 남깁니다.

## 개선점의 소유권

| 개선 내용                                                                | 소유자                            |
| ------------------------------------------------------------------------ | --------------------------------- |
| 선호 추출·스킬 선택 조건·본문과 참고 문서 배치·스킬 경계·검색·설치·배포  | `apm`                             |
| 의미를 보존한 한국어 표현·구와 문장·수식·목록 표현·같은 개념의 용어 통일 | `simple-korean`                   |
| 근거·독자 작업·정보 위치·Markdown 구조·API 설명에 담을 계약              | `documentation`                   |
| TS API·타입·모듈·런타임·수명·패키지·빌드 설정·TSDoc 문법                 | `typescript`                      |
| 시나리오·단언·격리·모킹·테스트 도우미·타입 단언 검증                     | `testing`                         |
| 업무 규칙·상태의 소유권·도메인 경계·의존 방향·공통화                     | `project-structure`               |
| 한글 Conventional Commit 메시지·승인 범위·스테이징·커밋·훅               | `git-commit`                      |
| 특정 저장소에 고정된 경로·설정·운영 정책                                 | 저장소 규칙·설정·소유 패키지 문서 |
| 특정 작업의 단계·임시 경로·일회성 승인                                   | 해당 작업 기록                    |

규칙의 정본은 해당 소유자 한 곳에 두고 다른 스킬에서는 필요한 적용 예만 보여 줍니다. 문장 정제 요청만으로 TS 구현·테스트·커밋까지 시작하지 않습니다.

## 스킬 경계 조정

| 사용 중 확인한 문제                   | 조정할 곳                                                                                                   |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 필요한 요청에서 스킬을 선택하지 못함  | `description`의 대상·작업·상황                                                                              |
| 범위 밖 요청에도 스킬이 선택됨        | `description`을 좁히고 범위 밖 지침 제거                                                                    |
| 특정 조건의 상세 내용이 본문을 차지함 | 같은 스킬의 `references/`로 분리하고 읽을 조건 연결                                                         |
| 다른 소유자의 규칙이 반복됨           | 해당 소유자의 정본으로 옮기고 이곳에는 작업에 필요한 적용 예만 유지                                         |
| 서로 다른 작업이 한 스킬에 섞임       | 기존 소유자의 범위로 먼저 재배치; 별도 요청·절차·산출물이 독립적이고 기존 소유자가 없을 때만 새 스킬로 분리 |

각 스킬은 다른 스킬·특정 저장소 문서를 필수로 읽지 않아도 담당 작업을 완료할 수 있게 씁니다. 실제 명령·설정을 근거로 읽는 것과 다른 스킬 없이는 절차가 끊기는 구조는 다릅니다.
요청에 여러 담당 작업이 있을 때만 해당 스킬들을 함께 적용하고 판단·산출물의 소유권을 유지합니다. 필수 형제 호출 체인이나 형제 스킬을 가리키는 상대 링크는 만들지 않습니다.
스킬·참고 문서의 이름을 바꾸거나 삭제하면 본문에서 해당 문서를 읽을 조건과 경로도 갱신합니다.

## 검증

- 스킬명을 지정하지 않은 대표 요청과 범위 밖 요청으로 `description`의 선택 경계를 확인합니다.
- 사용자 수정·기존 규칙에 근거한 기본값이 남아 있고, 예외 조건과 확인할 결과가 구체적인지 대조합니다. 무근거한 새 제한, 중복 소유자, 필수 형제 호출이 없어야 합니다.
- 선택한 스킬·참고 문서·산출물을 실행 기록에서 대조합니다. 문서만 검토했다면 실제 선택 여부는 미확인으로 남깁니다.
- 이름·설명 메타데이터와 스킬 안의 상대 링크를 검사하고, 포함한 예제는 목적에 맞게 검증합니다.
